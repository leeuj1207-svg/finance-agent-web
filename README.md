# Finance Agent Web 1.2

아이폰 Safari에서 CSV를 브라우저 내부에서 분석하는 한국어 정적 웹앱입니다.
투자 계획·월간 결산, 지출 분류, 합성 데모를 제공합니다. **이 저장소는 공개 배포 준비용이며
아직 Pages 활성화나 실제 사이트 게시를 실행하지 않았습니다.**

## 공개 범위

실행 파일은 `site/`의 아래 7개뿐입니다.

```text
site/
  index.html
  styles.css
  app.js
  core.js
  data.js
  icon.svg
  .nojekyll
```

그 외에는 이 안내 문서, 로컬 민감 파일 제외 규칙과 GitHub Actions 검사·수동 게시 설정만 있습니다.
Python 분석 코드·원본 프로젝트의 Git 이력·실제 금융 CSV·개인정보·계좌번호·비밀키를 포함하지
않습니다. 커밋 작성자도 개인 이메일 대신 프로젝트용 noreply 주소를 사용합니다.
`data.js`의 기본 계획 금액과 데모는 공개용 합성 데이터이며 실제 거래 기록이 아닙니다.
**코드·기본 계획·데모는 누구나 내려받을 수 있습니다.** 실제 정보로 바꿔 커밋하지 마세요.

## 무료 Pages 게시 준비

GitHub Free는 공개 저장소의 Pages를 지원합니다. 조직 정책 등으로 제한되는 경우는 별도 확인이
필요합니다. GitHub 저장소가 공개되어 있는 것과 Pages 사이트가 게시된 것은 별개입니다.

검사 워크플로 **Check public static site**는 push·PR·수동 실행 때 검토한 파일의 SHA-256,
허용 목록, CSP, 합성 계산과 모바일 Chromium/iPhone WebKit의 로컬 CSV 분석을 검증합니다.
이 검사는 사이트를 게시하거나 Pages 권한을 사용하지 않습니다. 테스트 도구는 실행기의 임시
디렉터리에 설치하며 사이트 파일에 포함하지 않습니다. 화면 캡처·trace·실데이터 아티팩트는
생성하지 않습니다.

게시 워크플로 **Publish public demo (manual only)**는 수동 실행만 지원하며,
기본 브랜치와 기본값이 꺼진 게시 승인 체크박스가 필요합니다. 전체 검사가 통과한 동일 커밋의
`site/`만 업로드합니다. `pages: write`·`id-token: write`는 저장소 코드를 실행하지 않는
배포 작업에만 부여합니다. Pages를 자동으로 활성화하지 않습니다.

### 사용자가 실제 게시를 승인한 뒤에만

1. 이 저장소의 **Settings → Pages → Build and deployment → Source**에서
   **GitHub Actions**를 선택합니다. 별도의 자동 배포 템플릿은 추가하지 않아도 됩니다.
2. 지원되는 경우 **Settings → Environments → github-pages**에 기본 브랜치 제한과
   필수 검토자를 설정합니다. 승인 체크박스 자체는 별도 승인자를 강제하지 않습니다.
3. **Actions → Publish public demo (manual only) → Run workflow**에서 `main`과 게시할
   변경 내용을 확인합니다. 실제 사이트 게시를 원할 때만 승인 체크박스를 선택해 실행합니다.
4. 검사·빌드·배포와 필요한 환경 승인이 완료되면 **Settings → Pages → Visit site**에
   표시되는 실제 주소를 사용합니다. 이 준비 문서는 활성 사이트 주소나 게시 성공을 보장하지
   않습니다. 처음 게시까지는 URL이 동작하지 않을 수 있습니다.

push·PR·병합으로는 배포되지 않습니다. 현재 작업에서는 위 게시 워크플로를 실행하지 않았고,
다른 저장소의 비공개 설정도 변경하지 않았습니다.

## 아이폰 사용법

사용자가 승인하여 게시한 뒤 Safari에서 사이트를 엽니다. **합성 데모로 둘러보기**를 누르면
2026년 1월의 예시 결과를 볼 수 있습니다. 월을 고르고 투자 또는 지출 화면에서 ‘파일’ 앱의
UTF-8 CSV를 선택할 수도 있습니다. 필요하면 Safari 공유 메뉴에서 **홈 화면에 추가**를
사용하세요. iOS Safari 16.4 이상을 대상으로 하며 실제 기기 동작 확인은 별도 필요합니다.

- 투자 CSV: `date,account,symbol,amount`, 선택 열 `kind,transaction_id`.
  계좌 별칭은 `new_funds`, `pension`, `irp`, `isa`입니다.
- 현금성 적립은 `symbol=CASH-RESERVE`, `kind=reserve`로 기록합니다. 상품 매수와 구분합니다.
- 지출 CSV: `date,merchant,amount,description`. 메모는 비워도 됩니다.
- 파일당 2MB 이하, UTF-8 BOM·따옴표·쉼표를 지원합니다. XLSX는 지원하지 않습니다.
- 실제 금융 파일을 저장소·Issue·PR·Actions에 올리지 마세요. 계좌번호나 비밀키도 넣지 마세요.

파일과 분석 결과는 브라우저에서만 처리하며 서버에 업로드하거나 영구 저장하지 않습니다.
`connect-src 'none'`과 `form-action 'none'`을 유지합니다. 새로고침 시 초기화되며 Safari가
탭을 메모리에 복원할 수 있으므로 사용 후 **기록 지우기**를 권장합니다. 처음 화면을 받을
연결은 필요하고, 서비스 워커나 오프라인 첫 실행 기능은 없습니다. 호스팅 서비스는 방문 IP 등
접속 메타데이터를 수집할 수 있습니다.

## 후속 변경 검토

검사 워크플로에는 검토한 7개 파일의 해시가 고정되어 있습니다. 향후 정적 파일을 갱신하면
공개될 내용과 합성 데이터 여부를 다시 검토하고 해시도 의도적으로 갱신해야 합니다.
해시 검사는 검토된 파일이 바뀌지 않았음을 확인하며 개인정보를 자동으로 판별하지는 않습니다.
수정 후에는 검사·모바일 브라우저 테스트를 통과시킨 뒤 별도로 게시를 승인하세요.
CSV·비밀 파일 등은 `.gitignore`로 제외하지만 강제 추가나 과거 Git 이력까지 차단하지는
못합니다. 커밋 전에도 공개될 파일 목록을 반드시 확인하세요.
